## 1. 背景与价值

### 问题陈述

当前用户注册、个人资料及家庭成员资料涉及年龄、出生年月和性别等个人信息。为减少不必要的信息收集，用户和家庭成员不应被要求提供年龄；用户应能自主决定是否提供、保留自己及家庭成员的出生年月和性别。

### 用户故事

作为健康记录平台用户，我希望自己和家庭成员的年龄由自愿提供的出生年月计算，且能选择填写、修改或清除出生年月和性别，从而控制个人及家庭成员资料并继续使用健康记录功能。

### 业务价值

减少强制收集的个人信息，提升用户对个人资料的控制；避免手工年龄随时间失效，并确保缺少出生年月不会阻碍平台使用。量化目标待产品运营数据具备后再确定。

### 目标用户

注册用户、已有账户用户及其家庭成员，包括系统生成的 Self 成员。

## 2. 范围与边界

### In Scope

- 注册时不要求用户填写年龄；用户出生年月和性别均为可选。
- 创建家庭成员资料时不要求提供年龄；家庭成员出生年月和性别均为可选，包括 Self 成员。
- 用户或家庭成员自愿提供出生年月时，精度为年、月，不采集具体出生日；系统据此计算并展示对应年龄。
- 用户或家庭成员未提供出生年月时，不展示对应年龄，也不要求补充。
- 用户可在个人资料中修改或清除自己的出生年月和性别，也可修改或清除家庭成员（包括 Self）的出生年月和性别。
- Self 的出生年月和性别可按本需求修改或清除；Self 身份及成员记录仍受现有保护规则约束。
- 清除出生年月后停止展示该用户或家庭成员的派生年龄；清除性别后不再显示已清除的性别。
- 已有用户或家庭成员缺少出生年月时，无需补录且不受功能限制。
- 保留已有用户资料、家庭成员资料和健康记录；本需求不进行历史资料或健康记录迁移。

### Out of Scope

- 采集完整出生日期或具体出生日。
- 基于年龄的报表、筛选或统计功能。
- 修改或删除 Self 成员身份、名称或成员记录。
- 修改或替代 Issue #11；本需求仅由 Issue #12 跟踪。

## 4. 非功能要求

| 领域 | 要求，或填写 `不适用` 并说明理由 |
|---|---|
| 性能 | 用户及家庭成员资料加载与保存不应因年龄派生产生可感知的性能下降。 |
| 安全 | 用户及家庭成员的出生年月、性别和派生年龄按个人资料处理；未填写或已清除的值不得继续展示为有效资料。 |
| 国际化 | 中英文界面中用户及家庭成员资料的字段名称、可选状态及年龄展示保持一致。 |
| 审计 | 不新增个人资料访问审计要求；遵循平台现有用户及家庭成员资料变更记录规则。 |
| 可用性 | 用户及家庭成员的出生年月与性别可独立填写、修改和清除；缺少任一字段不阻断注册或正常使用。 |

## 5. 数据与隐私

| 数据 | 来源 | 目的 | 生命周期 / 保留 | 隐私分级 |
|---|---|---|---|---|
| 出生年月（年、月） | 用户为本人或家庭成员自愿填写 | 计算并展示对应年龄 | 用户可修改本人或家庭成员资料；清除后不再作为有效资料展示 | 个人信息 |
| 性别 | 用户为本人或家庭成员自愿填写 | 在对应资料中展示用户选择的信息 | 用户可修改本人或家庭成员资料；清除后不再作为有效资料展示 | 个人信息 |
| 派生年龄 | 由用户或家庭成员出生年月计算 | 在出生年月有效时展示对应年龄 | 随出生年月变化；清除出生年月后停止展示 | 个人信息 |

本需求不要求迁移或改写既有用户资料、家庭成员资料及健康记录。历史资料的后续处理不在本需求范围内。

## 6. 发布与回滚预期

### 发布

- 对新注册用户、已有用户及其家庭成员统一开放可选填写及资料自主管理能力。
- 发布验收信号：AC-01 至 AC-08 通过，且已有用户及家庭成员未补录出生年月仍可正常使用。

### 回滚

- 回滚不得要求用户补录出生年月或年龄。
- 回滚不得恢复用户或家庭成员已清除的出生年月或性别；已有用户资料、家庭成员资料及健康记录必须保持不变。
