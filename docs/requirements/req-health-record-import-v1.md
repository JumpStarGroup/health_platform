# Requirement: 健康记录批量导入（CSV/Excel）v1

> 状态：Draft（已与需求方确认关键决策）
> 
> 追踪：待创建/绑定 GitHub Issue（后续补充）

## 1. 背景 & 价值
- **用户故事**：作为健康记录平台的用户，我希望能从其他系统导出的 CSV/Excel 文件导入健康记录，并在导入前预览与校验，确认无误后再写入系统，从而快速迁移历史数据、减少手工录入。
- **业务价值**：
  - 降低迁移门槛与录入成本，提高留存与数据完整度。
  - 通过校验与预览减少“脏数据”进入系统，提升后续分析与趋势图的可信度。
  - 支持家庭多成员场景（同一文件多成员），提升可用性。

## 2. 范围 & 边界

### 2.1 本期目标（v1 In-Scope）
- **文件导入**：支持 CSV 与 Excel 两种文件格式导入。
- **逐行导入语义**：文件中 **每一行 = 系统中一条健康记录**（不做聚合反推、拆分生成等“智能衍生”）。
- **标准模板**：提供“标准导入模板”（CSV/Excel），引导用户按平台字段填写。
- **字段映射（列名对应）**：即使用户未使用标准模板，也允许在导入流程中将文件列映射到平台字段（本次导入有效，不做长期保存/复用）。
- **预览与确认**：用户需经历“上传 → 预览（含校验结果）→ 确认导入 → 查看结果/下载报告”的流程。
- **成员处理（多成员支持）**：
  - 支持“一份文件包含多个成员”的导入。
  - 若导入行引用的成员不存在：在预览阶段列出“将新建的成员清单”，**用户勾选确认后**才创建并导入。
- **重复数据处理**：同一成员在**同一分钟**的重复记录，导入时 **跳过（忽略）**，保留系统已有数据；需要在结果中统计并可导出。
- **结果与报告**：导入完成后展示摘要（总行数、成功数、失败数、跳过数），并支持下载“错误/跳过明细报告”。
- **限制与规模**：单次导入最多 **500 行**；单文件大小限制 **5MB**。
- **审计追溯**：记录“谁、何时、导入了哪个文件（标识/文件名）以及导入摘要统计”，用于追溯。

### 2.2 不在本期（v1 Out-of-Scope）
- 对任意第三方系统格式的“全自动识别与单位换算”（v1 仅提供标准模板 + 手动映射能力）。
- 导入配置（映射规则）保存为可复用模板。
- 导入回滚/撤销（无需支持撤销）。
- 异步大文件导入、进度条到秒级实时更新（v1 规模小，先用同步/短时处理即可；体验上可用“处理中”状态）。

## 3. 标准字段（用户可见）

### 3.1 平台字段（标准模板字段）
- 成员名称（必填）
- 测量时间（必填）
- 收缩压（必填）
- 舒张压（必填）
- 心率（选填）
- 标签（选填，可多个）
- 备注（选填）

### 3.2 字段映射要求
- 用户必须完成“必填字段”的映射，才能进入“确认导入”。
- 对于标签字段：允许用户在说明中看到支持的分隔方式（例如分号/逗号），以减少导入失败。
- 映射仅对本次导入有效，不要求保存。

## 4. 规则与校验（业务层）

### 4.1 必填校验
- 成员名称、测量时间、收缩压、舒张压不能为空。

### 4.2 数值与关系校验
- 血压范围：30–250 mmHg。
- 收缩压必须大于舒张压。
- 心率（如填写）：30–150 bpm。

### 4.3 时间与时区
- 若文件时间不包含时区信息：按 **北京时间（UTC+8）** 理解。
- 若包含时区信息：按其原始时区理解。

### 4.4 重复数据（去重）
- 判定维度：同一成员 + 同一分钟。
- 处理方式：导入行 **跳过（忽略）**，不覆盖、不插入。
- 跳过行需在结果统计中体现，并可导出明细。

### 4.5 成员不存在时的处理
- 预览阶段列出“将新建成员清单”，默认不自动创建。
- 用户勾选确认后：允许创建这些成员并继续导入。
- 若用户不确认创建：对应行应标记为失败/不可导入，并在报告中解释原因。

## 5. 验收标准（Acceptance Criteria）
- [ ] AC1：用户可以上传 CSV 或 Excel，并看到预览表格（至少展示前 N 行）以及每行的校验状态。
- [ ] AC2：用户可以进行字段映射；若必填字段映射不完整，则无法进入“确认导入”。
- [ ] AC3：预览阶段会对每行执行校验，并能区分：可导入、失败（错误）、跳过（重复）。
- [ ] AC4：若文件包含多个成员，系统能按行正确归属到对应成员。
- [ ] AC5：当出现“成员不存在”时，系统在预览阶段展示“将新建成员清单”；仅在用户勾选确认后才会创建并导入相关行。
- [ ] AC6：导入完成后显示摘要：总行数、成功数、失败数、跳过数。
- [ ] AC7：用户可以下载“错误/跳过明细报告”，报告内容至少包含：行号、原始数据（或关键字段）、原因说明。
- [ ] AC8：导入限制生效：超过 500 行或 5MB 时，系统明确提示并阻止导入。
- [ ] AC9：系统具备可追溯审计记录：操作者、时间、文件标识/文件名、摘要统计。

## 6. 非功能性需求（NFR）
- **安全**：仅登录用户可导入；只能导入到自身家庭/成员范围内。
- **可靠性**：支持“部分成功”：错误行不影响其他有效行导入。
- **可用性**：预览阶段信息清晰（至少包含错误原因与跳过原因），降低用户反复试错。
- **国际化/兼容性**：在列名映射时应对中英文列名友好（通过映射而非强依赖固定列名）。
- **性能**：在 500 行规模下，导入处理时间应保持可接受（可在后续定义目标 SLA，例如 <10s）。
- **隐私**：审计记录仅保留必要元数据（谁/何时/摘要/文件名等），不要求长期保存原始文件内容（后续如需保存再单独立项）。

## 7. 待澄清（后续可选增强）
- 是否需要“映射配置保存为模板”以便下次复用。
- 是否需要“导入历史列表”让用户可查看每次导入的记录与下载报告。
- 是否需要更灵活的格式兼容（常见设备/系统的自动列名识别、单位换算、字段推断）。
