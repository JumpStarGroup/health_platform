# Task 01 - Delete namespace resources created during the exercises

## Introduction

In this workshop, you deployed your Health Platform application to a **shared AKS cluster** using a **namespace derived from your Git branch name**. To clean up your environment and reclaim cluster resources (including LoadBalancer allocations), you must delete your namespace.

## Description

This task outlines the steps to clean up the Kubernetes namespace you created during this lab.

The **preferred method** is to delete your namespace using `kubectl`, which removes all resources (Deployments, Services, LoadBalancers, etc.) provisioned within that namespace.

Manual cleanup via Azure Portal is not applicable in this shared cluster model—the workshop admin manages the cluster, and learners clean up by deleting their own namespaces.

## Success Criteria

- Your branch-derived namespace has been deleted from the shared AKS cluster.
- All resources within the namespace (including the LoadBalancer Service) have been removed.
- You have verified no lab resources remain in the cluster.

## Key Tasks

### 01: Determine Your Namespace Name

Your namespace was derived from your Git branch name using the workflow's normalization logic.

<details markdown="block">
<summary><strong>Expand this section for detailed steps</strong></summary>

1. Check your most recent GitHub Actions workflow run to see the computed namespace:
   - Go to your repository → **Actions** tab
   - Select the most recent `Build and Deploy to AKS` workflow run
   - Look for the step "Compute namespace from branch" in the logs

2. Alternatively, if you know your branch name, you can compute it manually:
   - Normalize: lowercase, replace `_` with `-`, remove special chars
   - Add hash suffix if needed (workflow logic)
   - Example: branch `feature/my-app` → namespace `feature-my-app-abc123`

3. Save your namespace name for the next step (e.g., `feature-my-app-abc123`).

</details>

### 02: Delete Your Namespace

Use `kubectl` to delete your namespace and all resources within it.

> **WARNING** Deleting a namespace is irreversible. All resources (Deployments, Services, LoadBalancers) in the namespace will be permanently removed.

<details markdown="block">
<summary><strong>Expand this section for detailed steps</strong></summary>

1. Ensure you have `kubectl` installed and configured to access the shared cluster:
   - If the workshop admin provided a kubeconfig file, load it:
     ```bash
     export KUBECONFIG=path/to/your-kubeconfig.yaml
     ```

2. Verify you can access the cluster:
   ```bash
   kubectl get namespaces
   ```

3. Delete your namespace (replace `<your-namespace>` with your actual namespace):
   ```bash
   kubectl delete namespace <your-namespace>
   ```

4. This command will:
   - Delete all Deployments, Pods, Services (including LoadBalancer), ConfigMaps, Secrets, etc.
   - Reclaim the public IP allocated to the LoadBalancer Service
   - Remove the namespace itself

5. Wait for the deletion to complete (usually takes 30-60 seconds).

</details>

### 03: Verification

Verify that your namespace and all resources have been removed from the cluster.

<details markdown="block">
<summary><strong>Expand this section for detailed steps</strong></summary>

1. Confirm the namespace no longer exists:
   ```bash
   kubectl get namespace <your-namespace>
   ```
   Expected output: `Error from server (NotFound): namespaces "<your-namespace>" not found`

2. Verify no resources remain in the deleted namespace:
   ```bash
   kubectl get all -n <your-namespace>
   ```
   Expected output: `No resources found in <your-namespace> namespace.` or `namespace not found` error.

3. (Optional) Check that the LoadBalancer public IP has been released:
   - Contact the workshop admin if you need confirmation
   - Or check the Azure Portal (if you have access) for the AKS cluster's public IP resources

</details>

## Summary

You've completed this task. Your branch-derived namespace has been deleted from the shared AKS cluster, and all resources (including the LoadBalancer Service) have been removed.
