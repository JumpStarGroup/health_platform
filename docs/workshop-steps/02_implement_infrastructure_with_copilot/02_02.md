# Task 02 - Review the Kubernetes deployment workflow with Copilot

## Introduction

The infrastructure is already set up for you. In this task you will review the existing CI/CD workflow and Kubernetes manifests that perform deployments to the shared AKS cluster.

## Description

Use Copilot Chat in VS Code to:

- Understand how the workflow builds/pushes images to GHCR
- Understand how the workflow computes **namespace from branch**
- Identify which GitHub Secrets/Variables are required for a successful deploy
- Locate the Kubernetes template used for deployment, including ResourceQuota/LimitRange and LoadBalancer exposure

## Success Criteria

- You can point to the workflow that deploys to AKS
- You can explain where the namespace comes from and why it is stable per branch
- You can list the minimum required GitHub Environment secrets
- You can identify where LoadBalancer exposure is configured

## Key Tasks

### 01: Review the deployment workflow

Review the GitHub Actions workflow that builds images and deploys to the shared AKS cluster.

<details markdown="block">
<summary><strong>Expand this section for detailed steps</strong></summary>

1. Open the workflow file:
   - `.github/workflows/Build-Deploy-K8S.yml`

2. In Copilot Chat, ask:

    ```text
    @workspace Walk me through .github/workflows/Build-Deploy-K8S.yml.
    Explain: (1) when it triggers, (2) image tags pushed to GHCR,
    (3) how the namespace is computed from the branch,
    (4) which secrets/vars must exist for deploy to succeed.
    ```

3. Locate and read the step “Compute namespace from branch”.

4. Locate and read the step “Create imagePullSecrets for GHCR”.

</details>

### 02: Review the Kubernetes deployment template

Review the Kubernetes template used by the workflow, including namespace guardrails and LoadBalancer exposure.

<details markdown="block">
<summary><strong>Expand this section for detailed steps</strong></summary>

1. Open the deployment template:
   - `deploy/k8s-template.yaml`

2. In Copilot Chat, ask:

    ```text
    @workspace Explain what deploy/k8s-template.yaml creates.
    Identify the ResourceQuota/LimitRange guardrails and where the frontend
    Service type is set to LoadBalancer.
    ```

3. Find these key objects in the template:
   - `Namespace`
   - `ResourceQuota`
   - `LimitRange`
   - `Deployment` (backend + frontend)
   - `Service` (backend ClusterIP, frontend LoadBalancer)

</details>

## Summary

You've completed this task. You can locate and explain the existing AKS deployment workflow and the Kubernetes template that enforces guardrails and exposes the frontend via LoadBalancer.
