# Task 01 - Collect content and define a slide outline

## Introduction

Before generating slides, you need a clear narrative: what you built, why it matters, and how to validate it.

In this task, you will collect inputs from the repository and produce a slide outline that can be converted into a PPTX deck.

## Description

You will review the main workshop outputs (CI/CD workflow, deployment templates, and security exercises), then summarize them into an outline with a small number of slides.

## Success Criteria

- You have identified 6–10 key points worth presenting
- You have drafted a slide outline (titles + bullets)
- Any diagrams/screenshots you plan to include are stored under `docs/media` and referenced via `../../media/...`

## Key Inputs

Use these as your sources of truth:

- CI/CD: `.github/workflows/Build-Deploy-K8S.yml`
- Kubernetes template: `deploy/k8s-template.yaml`
- Workshop step docs: `docs/workshop-steps/02_*` → `04_*`
- Security: `docs/workshop-steps/04_github_advanced_security/*`
- Versioning: `VERSION` and `docs/API_Design.md` (if applicable)

## Key Tasks

### 01: Create a short slide outline

<details markdown="block">
<summary><strong>Expand this section for detailed steps</strong></summary>

1. Draft slide titles first (example):
   - Title
   - TL;DR
   - Architecture (Client → Service → Manager → Models)
   - Deployment model (branch → namespace)
   - CI/CD pipeline highlights
   - Security controls (GHAS)
   - Next steps

2. For each slide, add 3–6 bullets max.

3. Keep the outline stakeholder-friendly:
   - Use outcomes ("deployed to shared AKS") over implementation trivia
   - Include one validation method per key claim ("Actions run logs", "kubectl get", "Security tab")

</details>
